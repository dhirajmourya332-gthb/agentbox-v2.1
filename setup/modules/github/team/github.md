# GitHub rules (example: edit to fit your team)

Agents read this before creating or editing issues and PRs.

## Where work is tracked
- Organisation: `acme` (replace)
- Project board: `Acme - Scrum` (org project #1) (replace, or delete this line if you don't use Projects)
- Iteration: set new issues to the current iteration, if the board has one.

## Issues
- Assign new issues to: `your-github-login` (replace)
- Labels: `bug`, `enhancement`, `chore`; add `needs-owner` when a decision is yours.
- Title: imperative, under 70 characters. Body: context, what done looks like, links.

## Pull requests
- Link the issue (`Closes #123`).
- Keep PRs small; one concern each.
- Never merge your own PR unless the owner said so.
